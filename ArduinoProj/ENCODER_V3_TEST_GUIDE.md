# Encoder controller V3 — ทดลองโดยไม่ใช้ Gyroscope

## ไฟล์ใช้งาน

เปิด `combined_encoder_v3/combined_encoder_v3.ino` ใน Arduino IDE แล้วเลือก UNO R4 WiFi ไฟล์นี้เป็นสำเนา standalone จาก `combined_state_sequence.ino` เพื่อไม่ให้ Arduino IDE รวม `SPEED.ino` และ `generated_route.ino` ที่มี setup/loop ของตัวเองเข้าด้วยกัน

ต้นฉบับสำหรับพัฒนาคือ `combined_state_sequence.ino` และ `encoder_motion/EncoderMotion.h` หลังแก้ต้นฉบับให้รัน:

```sh
python3 tests/sync-encoder-controller.py
python3 tests/prepare-combined-sketch.py
```

หากแก้ค่าในไฟล์ standalone เพื่อทดลอง ควรนำค่าที่ผ่านการยืนยันกลับมาต้นฉบับก่อน regenerate ไม่เช่นนั้นจะถูกเขียนทับ

## เปลี่ยนอะไรแล้ว

- Combined ส่งผลล้มเหลวกลับไปยัง setup: timeout, ไม่มี tick 2 วินาที, ล้อเลี้ยวถึงเป้าไม่ทันกันเกิน 500 ms, หรือรอ Encoder นิ่งไม่สำเร็จ จะไม่ไป state ถัดไป
- รออย่างน้อย 500 ms และไม่มี tick เพิ่มอย่างน้อย 200 ms โดยมี deadline 2 วินาที ก่อนรับผลหลังหยุด การไม่มี tick เป็นเพียงหลักฐานโดยประมาณของการหยุด ไม่รับประกันว่ารถไม่ลื่นหรือเคลื่อนต่ำกว่าความละเอียด Encoder
- Encoder replay สำหรับเลี้ยวใช้โปรไฟล์ความเร็วตามระยะเหลือและสัดส่วนความคืบหน้า L/R พร้อม PI แยกล้อ ไม่มีการ re-kick ซ้ำระหว่างล้อติด
- ตัวควบคุมเลี้ยววัดความเร็วจากหน้าต่าง 100–200 ms ตามจำนวน tick ไม่ได้เพิ่มเซนเซอร์หรือใช้ Gyro
- Integral หยุดสะสมเมื่อผลลัพธ์ดันเกิน PWM ที่ทำได้ แต่ยอมให้คลายกลับ
- วิ่งตรงใน combined คงตาราง cumulative R-L และตัวควบคุมเดิมเป็นหลัก เพิ่ม stall detection, anti-windup, การลดความเร็วปลายทาง และรอเก็บ tick หลังปล่อยไหล
- generated_route และตัว export ใช้ส่วน profile/PI เดียวกับ encoder replay แต่ไม่ได้คัดลอกตาราง R-L สำหรับเส้นทาง 4–5 เมตรไปใช้กับเส้นทางอื่น
- generated_route รายงาน heading ว่าเป็นค่าตามแผน ไม่ใช่มุมวัดจริง; ยังไม่ได้เพิ่ม odometry แบบวัดความต่างล้อ เพราะยังไม่มีค่าระยะห่างล้อ/สเกลแต่ละล้อที่ยืนยัน

## ค่าที่ต้องทราบก่อนทดสอบ

ลำดับเต็มของ combined ยังคงค่าที่มีในไฟล์ก่อนแก้: เดินหน้า 400 cm, หมุน 375 องศาทิศ -1, เดินหน้า 500 cm, หมุนซ้าย 375 องศา ชื่อ state เก่าบางชื่อมีคำว่า right/360 แต่ค่าที่ใช้จริงดูจาก STATE PLAN ใน Serial โปรแกรมนี้ไม่มีคำสั่งถอยหลังในลำดับ combined

ตาราง tick เดิมยังอยู่ครบ แต่เป็นเพียงค่าเริ่มต้น เพราะโปรไฟล์ความเร็วและการหยุดเปลี่ยนแล้ว ห้ามถือว่าค่าเดิมทำมุมเท่าเดิมโดยยังไม่วัดจริง ค่า 360° ใน combined ยังคงถูกใช้คูณสัดส่วนเมื่อทดสอบ 90°; ยังไม่มีข้อมูลเพียงพอสร้างตารางมุมใหม่

โปรไฟล์เลี้ยวเริ่มด้วย cruise 25 cm/s, crawl 10 cm/s, acceleration 30 cm/s², deceleration 40 cm/s² และ feedforward offset 600/4095 ทั้งหมดเป็นค่าตั้งต้นสำหรับทดลอง ไม่ใช่ผลคาลิเบรตใหม่ การประสานล้ออาจลดล้อที่นำต่ำกว่า crawl ได้; หากแรงไม่พอจะหยุดด้วย STALL แทนการกระชากซ้ำ

## ทดสอบเป็นขั้น

ค้นหา `ENCODER_TEST_MODE` ในไฟล์ standalone ก่อนอัปโหลด:

| ค่า | การทำงานครั้งเดียว |
|---|---|
| 0 | ลำดับสนามเดิมทั้งหมด (ค่าเริ่มต้นเพื่อคงพฤติกรรมเส้นทางเดิม) |
| 1 | เดินหน้า `ENCODER_TEST_DISTANCE_CM` เริ่มที่ 100 cm / 25 cm/s |
| 2 | เลี้ยวขวา `ENCODER_TEST_TURN_DEG` เริ่มที่ 90° |
| 3 | เลี้ยวซ้าย `ENCODER_TEST_TURN_DEG` เริ่มที่ 90° |

1. เริ่ม mode 1 บนพื้นจริงพื้นที่โล่ง เปิด Serial 115200 จดระยะตามแนวเป้าหมาย การเบนข้าง และมุมจริงหลังหยุด ทำซ้ำ 5 รอบ
2. ทดลอง mode 2 และ 3 อย่างละ 5 รอบ เก็บ STOP_COUNTS, FINAL_COUNTS, ENCODER_SETTLED และมุมจริงจากเทป/ภาพ ไม่ใช้มุม Gyro ในรายงานเก่าเป็นผลของเฟิร์มแวร์ใหม่นี้
3. ถ้ามี STALL ให้ตรวจว่าล้อติดจริงหรือ PWM ช่วงต่ำไม่พอ ก่อนปรับ feedforward/ความเร็วต่ำ อย่าแก้ด้วยการเพิ่ม timeout อย่างเดียว
4. เมื่อผลทำซ้ำได้ ค่อยปรับค่าระยะและตารางมุม จากนั้นตรวจซ้ำด้วยระยะ/มุมที่ใช้งานจริง
5. กลับ mode 0 เมื่อผลรายคำสั่งผ่านแล้ว ตรวจว่าระยะและทิศใน STATE PLAN เป็นเส้นทางที่ตั้งใจ

โปรแกรมหยุดเมื่อพลาด ไม่เริ่ม state ใหม่เพื่อกลบความผิดพลาด ส่ง Serial ตั้งแต่ FIRMWARE/STATE PLAN จนถึงผลจบ พร้อมระยะ/มุมที่วัดจริง เพื่อจูนรอบถัดไป

## การตรวจซอฟต์แวร์

```sh
NODE=/path/to/node python3 tests/run-encoder-tests.py
```

ชุดทดสอบครอบคลุม anti-windup, ขีดจำกัด PWM แบบ 8/12 บิต, การประสานล้อ, การชะลอ, แบบจำลองมอเตอร์อย่างง่าย, การหยุดลำดับ combined เมื่อ Encoder ไม่ขยับ และการสร้างโค้ดสำหรับสองบอร์ดพร้อมเปิด/ปิด Ultrasonic

ตรวจ object compilation ด้วย ARM compiler และ core UNO R4 WiFi 1.6.0 ที่ติดตั้งในเครื่องแล้ว แต่ยังไม่ได้ link เฟิร์มแวร์เต็ม/อัปโหลด/ทดลองรถจริง จึงยังยืนยันความแม่นยำมุมหรือระยะไม่ได้
